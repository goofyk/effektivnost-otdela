# Итерация 19: объяснение METHOD-находок — модель, неизвестная база, канал (дизайн)

Дата: 2026-11-24. Основание: критерий §12 п.4 дизайн-дока итерации 18 не выполнен буквально —
`why` есть у 495 из 3 287 METHOD-находок. Итерация 19 закрывает этот долг и раскладывает остаток
на корзины, а не гонится за новой ступенью лестницы.

## 1. Что показал разбор артефакта 87

METHOD-ось — **3 287 | 822**, с непустым `why` — **495 | 138**, без объяснения — **2 792 | 684**.
Пустые `why` распадаются не на одну причину:

1. **Тип известен по модели, имени в модели нет — 1 821 | 405 (65 %).** Владелец разрешён
   (`resolve_member` получает `TypeDef` с именем), но члена в модели нет: `ОбластьЯчеекТабличногоДокумента`
   **271 | 85**, `ДиалогВыбораФайла` **132 | 85**, `ТабличныйДокумент` **81 | 30**,
   `ЭлементБлокировкиДанных` **58 | 1**, `ЗначениеXDTO` **56**, `ЧтениеXML` **51** и ещё 599
   различных пар «тип, имя» (`ОбластьЯчеекТабличногоДокумента.Текст` 103, `.Объединить` 77,
   `ЭлементБлокировкиДанных.Режим` 48, `ЧтениеXML.ЛокаИмя` 34, `ДиалогВыбораФайла.ПолноеИмяФайла` 29).
   Это **пробел модели/реестра**, а не неизвестная база; фраза «тип не определён» здесь была бы
   ложной.
2. **Тип — `Неопределено` — 971 | 279 (35 %).** Владелец ровно `Неопределено`; проверка тип не
   вывела. База — простая переменная в **867**, выражение в **93**, цепочка свойств в **11**; по
   последнему присваиванию — выражение **539**, свойство **420**, параметр **8**, модульная **4**
   (зонд контролёра по тексту, не мера).
3. **Семейство с каналом, но без `why` — 34** (ТЗ 30 | 6, ЗАПРОС 4 | 0): привязка есть, запись
   пробела не создана.

Проверено реальным чекером на синтетических модулях: параметр процедуры и переменная `Для каждого`
**не дают METHOD-находки вовсе** (тип `None` — молчание, как у платформы); `В = Неопределено` даёт
`(Неопределено.Х)`, `В = "т"` — `(Строка.Х)`, `В = Новый Массив` — `(Массив.Х)`,
`В = Новый ТабличныйДокумент` — `(ТабличныйДокумент.Текст)`. Значит объяснять нужно три разных
семейства, и «происхождение» применимо только ко второму.

## 2. Цели

1. Заполнять `why` (и, где полезно, `hint`) у **каждой** METHOD-находки — тремя семействами:
   - **модель:** «база `<имя>`: тип `<Тип>` известен по модели; имени `<член>` в модели нет»
     (`hint`: проверить имя или дополнить модель/реестр);
   - **неизвестная база:** «база `<имя>`: тип не определён — <происхождение>; объявления типа в
     файле нет» (`hint`: проверить тип базы или объявить его);
   - **канал:** существующие формулировки каналов (колонки ТЗ, поля запроса, временные таблицы).
2. Для неизвестной базы вести **происхождение** последнего присваивания: `Неопределено`, из
   выражения, из свойства/цепочки, из вызова, из литерала, из `Новый`, модульная переменная, иное.
   Категории «параметр» и «переменная цикла» в население не входят — такие базы находок не дают;
   это записано, а не выброшено.
3. Снять замер **88**: `why` **3 287 | 822** (100 %), наборы троек (`code`, `file`, `line`) равны
   замеру 87, лестница неизменна (**926** / **4 344**), `stats.files` 1 195, подпись и фикстура
   не меняются.
4. Положить таблицу корзин: семейство объяснения × (тип, имя) для модели × происхождение для
   неизвестной базы × формная/корпусная строка — основание для следующей итерации. Крупнейшая
   корзина — **модель, 599 пар**, а не происхождение переменной.

## 5. Подходы

**A. Три семейства объяснений, происхождение — только для `Неопределено` (выбран).** Модельное
семейство — большинство и самое дешёвое (тип уже известен, нужно назвать его и отсутствие имени);
неизвестная база получает происхождение из последнего присваивания; каналы сохраняют свои тексты.
Лестница не двигается, критерий п.4 закрывается, таблица корзин честная.

**B. Только происхождение (первая редакция).** Отклонён: 65 % находок имеют известный тип, фраза
«тип не определён» для них ложна; 100 % `why` недостижимы.

**C. Сразу закрывать модельные пробелы.** Заманчиво (599 пар, 1 821 находка), но это правка
модели/реестра с собственным замером и риском ложных закрытий; критерий п.4 остался бы
невыполненным. Отклонён как отдельная итерация 20.

## 6. Механизм

1. **Модельное семейство.** В `_explain_member` (semantic.py): если база разрешилась в `TypeDef`
   с именем (не канальный маркер, не `Неопределено`), `why` = «тип `<t.name>` известен по модели;
   имени `<member>` в модели нет», `hint` = «проверьте имя или дополните модель/реестр». Тип и имя
   берутся из того же решения `resolve_member`, отдельного знания не требуется.
2. **Неизвестная база.** Если имя типа — `Неопределено`, `why` = «тип не определён — <происхождение>;
   объявления типа в файле нет». Происхождение ведёт карта формы `_gaps` (текстовый ключ
   `_base_key`, сброс на тело процедуры, как у `_tcols`/`_gaps`, **не** в `SVar` — иначе трогаем
   резолвер): при обходе `P.Assign` классифицируется правый операнд — `Неопределено`, `P.Call` →
   «вызов», `P.Member` → «свойство/цепочка», `P.New` → «конструктор», литерал → «литерал», иное
   выражение → «выражение», простая переменная → «переменная». Нет записи — «происхождение не
   установлено» (всё равно непустой `why`).
3. **Каналы.** Существующие ветви `_explain_member` (маркеры `ROW_TYPE_MARK`/`QUERY_TYPE_MARK`) и
   записи `_gaps` не меняются. Для 34 находок канальных семейств без `why` причина берётся из
   ближайшей записи `_gaps`; если её нет — «база `<имя>`: канал знает тип, но не знает объявления»
   (непустой `why`, без выдумывания).
4. **Что не меняется.** Решение о находке, код, текст, координаты; порядок каналов;
   `dynamic_members`; `check_queries`; грамматика sdbl. Правка только заполняет объяснение.
5. **Словарь.** Новые f-строки — по образцу `check/forms/checks.py:224-263`. Если `test_wording.py`
   даёт флаг — остановка «открыто владельцу», реестр охранителя не расширяется.

1. **Ложная фраза о типе.** Модель и происхождение берутся из решения проверки, а не из текста
   строки; тесты (а)…(г) держат каждое семейство. Цена ошибки — неверный `why`, решение не меняется.
2. **Движение лестницы.** Гейт сравнивает тройки 87/88; любое снятие или появление — откат и разбор.
3. **34 канальные находки.** Причина может отсутствовать; тогда честная фраза «канал знает тип, но
   не знает объявления», а не выдуманная.

   `scan_texts.py`; при флаге — остановка.

   обещание закрытия; числа корзин — мера зонда.
