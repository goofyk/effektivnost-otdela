# Что инструменты p1c говорят о преднамеренно сломанной конфигурации (отрицательные прогоны без платформы)

Материал: копия `cfg/ЭффективностьОтдела` с ровно одной преднамеренной поломкой
(`scripts/mutate.py`, исходник не трогается), копии в
`%TEMP%\opencode\p1c_effektivnost\mutate\<вид>`. Платформу эти замеры не запускают: они измеряют
**только** то, что видят инструменты p1c, и поэтому не зависят от того, чем закончится загрузка.

Команды запускались так (p1c установлен в окружение, модули доступны и как `python -m …`):

```
python -m p1c.check.forms.cli check <копия> --format text --no-parallel
python -m p1c.check.bsl.cli  check <копия> --root <копия> --format text
python -m p1c.load.cli       model <копия> --format text
python -m p1c.check.bsl.cli  check <один файл модуля> --format text
```

## 1. Сломанный обработчик события формы — находится

Поломка: из `Catalogs/Сотрудники/Forms/ФормаЭлемента/Ext/Form/Module.bsl` удалена процедура
`ПриСозданииНаСервере`, которая остаётся объявленной в `Ext/Form.xml`
(`<Event name="OnCreateAtServer">ПриСозданииНаСервере</Event>`).

`p1c-check-forms check` (код 1):

```
Catalogs/Сотрудники/Forms/ФормаЭлемента/Ext/Form.xml:5:10: error: BSL_FORM_EVENT_HANDLER_NOT_FOUND:
    Обработчик события формы не объявлен в модуле формы
    Объявите процедуру ПриСозданииНаСервере в модуле формы
итого: 2
skipped_rules: 3
```

Вывод: связка «описание формы ↔ модуль формы» инструментом покрыта, и покрытие лучше ожидаемого —
есть подсказка-исправление с именем недостающей процедуры.

## 2. Вызов несуществующей функции общего модуля — находится

Поломка: в `Documents/ФактРаботы/Ext/ObjectModule.bsl` добавлен вызов
`РасчётПоказателей.ПроверитьЧасыДокумента(Часы);`, которого ни один модуль не объявляет.

`p1c-check-bsl check <копия> --root <копия>` (код 1):

```
Documents/ФактРаботы/Ext/ObjectModule.bsl:21:26: error: IDS_STX_PROC_NOTDEFINED:
    Процедура или функция с указанным именем не определена (РасчётПоказателей.ПроверитьЧасыДокумента)
```

Вывод: имявнедрённой функции всплывает дословно, то есть сравним с диагностикой платформы по
файлу и строке (это и есть цель Task 19 — сверка p1c против платформы).

## 3. Ссылка подсистемы на несуществующий объект — НЕ находится ни одним проверенным инструментом

Поломка: в `Subsystems/ЭффективностьОтдела.xml` пункт содержимого
`<xr:Item xsi:type="xr:MDObjectRef">Catalog.Сотрудники</xr:Item>` заменён на `Catalog.ТакогоНет`.

- `p1c-load model <копия>` — вывод тот же, что и на целой конфигурации; ни одного упоминания
  подсистемы или несуществующего объекта;
- `p1c-check-bsl check <копия> --root <копия>` — про поломку молчит (находит только посторонние
  находки, см. раздел 4).

Вывод: **ссылочная целостность метаданных (содержимое подсистем, ссылки свойств) для p1c — слепая
зона.** Она согласуется с тем, что читатель `p1c.load` не читает коллекцию `Subsystems`
(`COLLECTIONS_MAP`, `p1c/src/p1c/load/reader.py:64-125`). Такую поломку ловит только платформа при
загрузке — а значит гейт не может от неё отказываться «дешёвым» статическим способом.

## 4. Ложные находки на **неполоманной** конфигурации: счётчик покрытие мерить нельзя без правки

`p1c-check-bsl check cfg/ЭффективностьОтдела --root cfg/ЭффективностьОтдела` на исходнике без
поломок даёт 11 `error`, из них 10 — на валидном коде модулей объекта:

```
Catalogs/Сотрудники/Ext/ObjectModule.bsl:7:10: error: IDS_STX_VAR_NOTDECLARED: Переменная не определена (ГрейдыСпециалистов)
Catalogs/Сотрудники/Ext/ObjectModule.bsl:17:7:  error: IDS_STX_VAR_NOTDECLARED: Переменная не определена (Ставка)
Catalogs/Сотрудники/Ext/ObjectModule.bsl:23:28: error: IDS_STX_VAR_NOTDECLARED: Переменная не определена (ДатаПриёма)
Documents/ФактРаботы/Ext/ObjectModule.bsl:9:28:  error: IDS_STX_VAR_NOTDECLARED: Переменная не определена (Сотрудник)
Documents/ФактРаботы/Ext/ObjectModule.bsl:15:7:  error: IDS_STX_VAR_NOTDECLARED: Переменная не определена (Часы)
Documents/ФактРаботы/Ext/ObjectModule.bsl:21:2:  error: IDS_STX_VAR_NOTDECLARED: Переменная не определена (Движения)
Documents/ФактРаботы/Ext/ObjectModule.bsl:22:2:  error: IDS_STX_VAR_NOTDECLARED: Переменная не определена (Движения)
Documents/ФактРаботы/Ext/ObjectModule.bsl:24:11: error: IDS_STX_VAR_NOTDECLARED: Переменная не определена (Движения)
InformationRegisters/ПланЗагрузки/Ext/ManagerModule.bsl:20:35: error: IDS_STX_EXP_SEMICOLON: Ожидается символ ';'
```

Смысл: в модуле объекта движок не связывает **неявные реквизиты объекта** (`Ставка`, `Часы`,
`Сотрудник`, `ДатаПриёма` — в 1C в модуле объекта они доступны по имени), **стандартные свойства**
(`Движения` — каноническое обращение в `ОбработкаПроведения`) и **предопределённые значения
перечислений** (`ГрейдыСпециалистов.Специалист`). Цена: «сколько находок» как метрика качества
конфигурации сейчас на 90 % состоит из шума, и найти среди шума настоящую поломку (раздел 2)
удалось только потому, что имявнедрённой функции совпало с текстом диагностики.

Отметка о контексте: при проверке **одного файла** (`…/Form/Module.bsl` отдельно) всплывает
ещё и `IDS_STX_VAR_NOTDECLARED: Переменная не определена (РасчётПоказателей)` — общего модуля
движок при одиночном файле не видит; при проверке каталога конфигурации этой находки нет.
Отсюда практическое правило для конура: **p1c-check-bsl запускать на каталоге конфигурации с
`--root`, а не по файлам** (иначе часть находок — артефакт отсутствия контекста).

## 5. Настоящая находка в нашей рукописной конфигурации (исправлено)

`p1c-check-forms check cfg/ЭффективностьОтдела` на исходнике:

```
Catalogs/Сотрудники/Forms/ФормаЭлемента/Ext/Form/Module.bsl:25:1: error: IDS_RTE_NEVENTPARAMS_NOTMATCH:
    Несоответствие числа параметров обработчика числу параметров события
    Официальная сигнатура события AfterWrite: 1–1 параметров
итого: 1
```

У нас было `Процедура ПослеЗаписи(ПослеЗаписи, ПопыткиЗапиji)` (2 параметра) при объявленном
в `Ext/Form.xml` событии `AfterWrite`. Исправлено на `Процедура ПослеЗаписи(ПопыткиЗаписи)`.
Это единственный класс находок, который p1c нашёл сам, без участия платформы и безвнедрённой
поломки, — и именно его `/CheckModules` платформы (см. `docs/evidence/iteration1-observations.md`)
не показал бы: платформа проверяет синтаксис модулей, а не соответствие обработчика событию формы.

## 6. Открытый вопрос после этих замеров

- `p1c-check-forms` и `p1c-load` при разборе нашей 24-файловой конфигурации печатают
  `[context] XML разобран: объектов 7, форм 1, модулей к сканированию 16`, хотя BSL-модулей в
  конфигурации 5. Что именно считается 16 «модулями к сканированию» — разобраться отдельным
  замером: от этого зависит, что означает `skipped_rules: 3/7` и все числа покрытия.
