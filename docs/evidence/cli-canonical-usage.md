# Как эту CLI-команду пишут живые конфигурации: канон употребления (шесть корпусов)

Замер `probe/corpora_cli_usage.py` → `reports/corpora-cli-usage-16.json`. Платформу не запускает,
исходник не меняет. Ищет дословные вхождения имён команд и опций во все файлы корпусов
(`.bsl`, `.txt` макетов), считает вхождения и приводит цитаты с файлом и строкой.

Корпуса прочитаны (файлов): `ai_chat` 239, `erp` 120 761, `lso` 10 835, `pulsar` 5 476,
`ssl` 12 696, `uh` 92 226. Пропущен один корпус: `corpora_cf` (в `corpora_skipped` во всех
замерах контура).

## 3. Канон формы команд обновления и проверки ИБ (макет файла обновления)

Один и тот же макет лежит во всех пяти больших корпусах:
`DataProcessors/УстановкаОбновлений/Templates/МакетФайлаОбновленияКонфигурации/Ext/Template.txt`
(ERP стр. 812–872, SSL стр. 812–872, LSO/Pulsar стр. 802–862, УХ стр. 837). Дословно:

```txt
// /LoadCfg<имя cf файла> (для базовых версий не используется) загрузка конфигурации из файла
'DESIGNER {0} {1} /LoadCfg "{2}" /Out "{3}" /UC{4} /DisableStartupMessages /DisableStartupDialogs',          (erp/ssl: 812, 816)
'CONFIG {0} {1} /LoadCfg "{2}" /Out "{3}" /UC{4} /DisableStartupMessages /DisableStartupDialogs',            (lso/pulsar: 802, 806)

// /UpdateCfg<имя cf | cfu файла> обновление конфигурации, находящейся на поддержке
'DESIGNER {0} {1} /UpdateCfg "{2}" /Out "{3}" /UC{4} /DisableStartupMessages /DisableStartupDialogs',        (erp/ssl: 830, 834)
'CONFIG {0} {1} /UpdateCfg "{2}" /Out "{3}" /UC{4} /DisableStartupMessages /DisableStartupDialogs',          (lso/pulsar: 820, 824)

// /UpdateDBCfg - обновление конфигурации базы данных
'DESIGNER {0} {1} /UpdateDBCfg -server /Out "{2}" /UC{3} /DisableStartupMessages /DisableStartupDialogs',    (erp/ssl: 848, 852)
'CONFIG {0} {1} /UpdateDBCfg -server /Out "{2}" /UC{3} /DisableStartupMessages /DisableStartupDialogs',      (lso/pulsar: 838, 842)

'DESIGNER {0} {1} /IBCheckAndRepair -IBCompression /Out "{2}" /UC{3} /DisableStartupMessages /DisableStartupDialogs',  (erp/ssl: 872)
'CONFIG {0} {1} /IBCheckAndRepair -IBCompression /Out "{2}" /UC{3} /DisableStartupMessages /DisableStartupDialogs',    (lso/pulsar: 862, uh: 837)
```

Замечаемые детали канона:

1. `{0}` — путь ИБ **без** `/F` (в макете его подставляет вызывающий код), `{1}` — блок
   авторизации (`/N"<имя>" /P"<пароль>" /WA-`), `{2}`/`{3}` — файлы вывода и кодировки. Наш
   контур держит `/F <иб>` явно: это отличие от макета, а не повторение макета, и оно
   зафиксировано в `scripts/exec_probe.py`.
2. `-server` в `/UpdateDBCfg -server` пишется строчными в макете корпуса; имя из таблицы имён
   платформы — `-Server` (`docs/evidence/cli-flag-names.md`). Наш контур использует измеренное
   имя `-Server` и называет расхождение регистра неизмеренным вопросом.
3. `/DumpConfigToFiles` в живых конфигурациях вызывается только как элемент массива
   `ПараметрыСистемы.Добавить("/DumpConfigToFiles")` (`CommonForms/ПроверкаФайлаОбновления/Ext/Form/Module.bsl:74`
   в erp/lso/pulsar/ssl) и `КомандаЗапуска.Добавить("/DumpConfigToFiles")`
   (`CommonModules/ДополнительныеОтчетыИОбработки/Ext/Module.bsl:2535` в erp, `:2519` в ssl,
   `:2311` в lso, `:2312` в pulsar) — то есть канон выгрузки есть, канона `DumpCfg`/`DumpDBCfg`
   нет вовсе.

## 4. Следствие для инструментов p1c

1. **p1c не знает канона.** Ни один модуль `p1c/src/p1c/**/cli.py` не сверяет имена команд и
   опций ни с таблицей имён платформы, ни с каноническим употреблением: argv собирается
   вручную, и в `p1c/src/p1c/test/run.py` и `p1c/src/p1c/debug/debug.py` сборка битая
   (см. `docs/evidence/exec-modes-and-negatives.md`). Канон лежал в этих же репозиториях
   корпусов всё время — его просто не читали.
2. **Порядок аргументов — не произвольный.** Каноническая форма ставит модификаторы опций
   **после** имени команды и её аргумента (`/LoadConfigFromFiles <каталог> -listFile <файл>`),
   затем `/Out`, затем `/DisableStartup…`. Наш контур повторяет этот порядок; форма «модификатор
   перед именем команды» сознательно не вводилась и остаётся неизмеренной.
3. **Частичная загрузка — опция, а не режим.** `-files`/`-listFile`/`-Format` имеют смысл только
   вместе (и исключают друг друга по описанию стр. 481, 483). Измеренное поведение совпадает с
   описанием: `docs/evidence/modifier-effects.md`.
4. **Канон `/UpdateDBCfg -server` объясняет, почему наш гейт обязан уметь обновлять ИБ, а не
   только загружать файлы**: живые конфигурации доводят загрузку до состояния базы именно этой
   командой, а не `/LoadConfigFromFiles`.

## 5. Что с этим делать (часть плана оптимизации p1c)

1. Проверять собираемый p1c argv по `test_cli_flags.json` (имя существует) и по канону
   употребления (место в строке): два независимых замера уже сделаны и лежат в
   `reports/corpora-cli-usage-16.json` и `p1c/src/p1c/data/test_cli_flags.json`.
2. Для выгрузки/загрузки конфигурации брать форму канона из БСП: `/LoadConfigFromFiles <каталог>
   -listFile <файл-список> /Out <файл> /DisableStartupMessages /DisableStartupDialogs`, а для
   применения к базе — `/UpdateDBCfg -Server`.
3. Считать каноническим только то, что подтверждено в >= 2 корпусах; одиночные написания
   (`-listFile` только в SSL) помечать как неизмеренные, а не как истину.
