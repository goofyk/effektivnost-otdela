# Дефекты в самих данных p1c (не в нашей конфигурации): два наблюдения с числами

Оба замера не запускают платформу и не меняют исходник. Инструменты замера:
`probe/p1c_name_pairs.py`, `probe/p1c_event_pages.py`, `probe/our_event_handlers.py`.

## 1. `PLATFORM_NAME_PAIRS` рассинхронизирован: 731 пара из 1520 переводят имя наоборот

Файл `p1c/src/p1c/data/platform_name_pairs.py` объявлен так:

```python
"""Пары имён платформы (EN-канон, RU) по официальным данным платформы 1C 8.3.27.1606."""
PLATFORM_NAME_PAIRS = [ ... ]
```

Оба читателя раскладывают его именно как `(en, ru)`:

- `p1c/src/p1c/graph/graph.py:44,50` — `from p1c.data.platform_name_pairs import PLATFORM_NAME_PAIRS`,
  `for _en, _ru in PLATFORM_NAME_PAIRS`;
- `p1c/src/p1c/metadata/model.py:393,396` — `for en_name, ru_name in PLATFORM_NAME_PAIRS`.

Замер (`probe/p1c_name_pairs.py`):

| измерено | число |
| --- | --- |
| пар всего | 1520 |
| пар, где первая часть кириллическая, а вторая латинская (то есть `(RU, EN)` в колонках `(EN, RU)`) | **731** |
| пар в объявленном порядке | 789 |
| первая такая пара | индекс 461: `('Низкая', 'Description')` |
| последняя такая пара | индекс 1197: `('ПометкаУдаления', 'EmptyRef')` |

Образец рассинхрона (EN-колонка отстаёт от RU-колонки на строку):

```
459 -> ('Presentation', 'Представление')     # порядок объявлен
460 -> ('Description', 'Описание')           # порядок объявлен
461 -> ('Низкая', 'Description')             # читается как en='Низкая', ru='Description'
462 -> ('Получить', 'Reset')                 # английская колонка съехала: должен быть 'Get'
463 -> ('Сбросить', 'Set')
464 -> ('Сбросить', 'Direction')
465 -> ('Направление', 'Data')
466 -> ('Данные', 'Clear')
467 -> ('Очистить', 'DataPath')
```

Правильные соответствия этой же области — `УникальныйИдентификатор` ↔ `UUID`,
`ПроверитьЗаполнение` ↔ `CheckFilling`, `Прочитать` ↔ `Read`, `Записать` ↔ `Write`,
`ПолучитьСсылкуНового` ↔ `GetNewObjectRef`, `ЭтоНовый` ↔ `IsNew` — то есть EN-колонка съехала
относительно RU-колонки (в районе строк 795–818: `("Заполнить", "UUID")`,
`("ЭтоНовый", "MainWindowModeFullscreenWorkplace")`).

Следствие: карта ru↔en имён, которую строят `graph.py` и `metadata/model.py`, в 731 случае даёт
неверное имя. Для русскоязычной конфигурации это означает, что инструмент может перевести имя
объекта или свойства на несуществующее английское имя (или наоборот) — и его находки в этой области
нельзя использовать без независимой сверки.

Отдельно, из этой же области: имя `Объект.Новый` контур не стал писать в форме — в 5903 канонических
модулях управляемых форм шести корпусов оно встречается **0 раз**
(`probe/corpora_default_places.py`), хотя `IsNew`/`ЭтоНовый` в данных p1c присутствуют (и стоят в
рассинхронизированной части списка пар).

## 3. Что с этим делать (часть плана оптимизации p1c)

1. Проверка сигнатур обработчиков модулей объекта — готовый источник данных уже есть в p1c
   (`EVENT_SIGNATURES` объектные страницы), не хватает только проверки; канон корпусов подтверждает
   арности независимо.
2. Проверка прав ролей — данных нет вовсе: в `p1c/src/p1c/data/` словаря прав доступа нет,
   `p1c-load` папки `Roles` не читает. Измеренный канон контур собрал сам
   (`docs/canonical-rights.json`: 1672 файла, 103 686 блоков, 27 видов, 66 имён прав, вида `Enum.` —
   0) и умеет проверять его статически (`scripts/rights.py`).
3. `PLATFORM_NAME_PAIRS` — починить рассинхрон (или заменить источник на пары, собранные из
   `test_events.json`, где `ru`/`en` стоят в одной записи и перепутать их нельзя).

### 5.4 Происхождение кодов находок подтверждено замером, а не началом имени

Каталог кодов p1c (155 кодов) до четвёртого пакета относил код к официальному по одному
признаку: начало `IDS_` читалось как «так кодит платформа». Добавлен замер имени кода по
файлам платформы 8.3.27.1606 — скрипт `p1c/scripts/extract_code_grounding.py` и закоммиченный
набор `p1c/src/p1c/data/codes_grounding.py` (схема `p1c.codes_grounding/v1`): 23862 имени
`IDS_*` в 476 файлах каталога `bin`, ответ записан по каждому коду каталога и набора SDBL
(всего 543 кода). Имя принимается только если оно ограничено с обеих сторон, иначе усечённая
запись длинного имени выглядела бы подтверждением: без этого условия тот же обход дал бы
25988 имён вместо 23862.

| Факт | Число |
| --- | --- |
| кодов в каталоге p1c | 155 |
| — официальный код платформы подтверждён замером | 133 |
| — собственных кодов | 22 (12 `BSL_*`, 8 `TEST_*`, 2 с платформенным началом имени) |
| кодов, для которых замера нет (`ungrounded_code`) | 0 |
| тексты: дословные / восстановленные / собственные формулировки | 130 / 3 / 22 |
| кодов SDBL, имени которых в платформе нет | 3 |

Измеренное расхождение. `IDS_STX_METHODNOTFOUND` и `IDS_STX_PROPERTYNOTFOUND` дают находки о
методе и о свойстве объекта и выглядят платформенными, но ни в одном ресурсном и ни в одном
исполняемом файле платформы такого имени нет — это собственные коды p1c. У первого стоял флаг
`exact_text: True`, то есть вывод утверждал дословность текста по официальной странице
справки; утверждение снято, оба кода помечены собственными, а их тексты — собственными
формулировками (в JSON и SARIF за это отвечают два поля, `code_origin` и `grounding`).
Три кода директив препроцессора остались официальными по имени, но с восстановленным текстом
(`approximate=True`): происхождение кода и подтверждённость текста — разные факты, а прежний
`is_approximate` отвечал на них иначе, чем `grounding`; теперь оба поля строятся по одному
разбору, и `ungrounded_code` существует как ответ, чтобы неподтверждённый код не читался
молча как официальный.

Закреплено проверками p1c: `tests/data/test_code_grounding.py` (543 записей, без замера 0;
`ABSENT` — 25 и ровно совпадает с `in_platform: False`; 2 кода каталога и 3 кода SDBL без
имени закреплены списком; `code_origin` сверяется с записью замера по каждому коду; путь
каталога платформы в скрипте не зашит), `tests/core/test_writers.py` (расхождение двух полей
показано на примере кода, которого в платформе нет, и на коде директивы препроцессора),
`tests/core/test_codes.py` (таблица кодов в README = вывод `scripts/measure_codes.py`).
Модулей слоя данных после добавления набора стало 14 (в 5.2 было 13), мёртвых — 0.

1. Что закрывает. Ничего — 0 закрытых находок; это предсказано до прогона (пункт 11 предсказаний) и

2. Где лежит сегодня. Имя `Стили` не входит в инвентарь имён: `inventory_names()`
